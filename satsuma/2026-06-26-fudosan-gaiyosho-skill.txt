## 🔒 共通ルール（全スキル横断）

以下の5点は全スキル共通のベストプラクティス。このスキルでも厳守する：

1. **スクショは最終確認1回のみ**: スクリーンショットは途中経過では撮らない。最終状態の目視確認として1回だけ使用する。
2. **長文入力はsetValue**: テキストエリア・Monaco エディタ等への長文入力は `type` アクションではなく `setValue()` / `setContent()` を使用する。
3. **固定wait禁止→ポーリング**: `wait(5)` 等の固定秒数待機は禁止。ログ出力や DOM 変化のポーリングで完了を検知する。
4. **WriteではなくEdit差分**: SKILL.md やコード等の既存ファイル修正は Write（全文上書き）ではなく Edit（差分修正）を使用する。
5. **TodoWriteは粒度**: TodoWrite の更新頻度は「段階完了時のみ」とし、細かいステップごとの更新は不要。

## 🔒 会社情報の完全匿名化ルール（最重要）

**目的**：仲介業者が概要書をそのまま顧客に転送・紹介しやすくするため、**見た人がどこの会社から出た資料か一切分からない状態にする**。

### 完全削除対象（一切の記載禁止）

以下は概要書HTML内に**一つも含めないこと**。テキスト・画像・URL・alt属性・HTMLコメント等あらゆる形式で禁止：

- 会社ロゴ（ロゴ画像・SVG・背景画像）
- 会社名（正式名称・略称・英語表記、大小文字問わず）
- 会社住所
- 電話番号
- メールアドレス（会社ドメインの全メール）
- 担当者名（個人名）
- 会社ドメインURL
- 会社SNS/公式サイトへのリンク

> ⚠️ 自社で運用している場合は、自社の会社名・住所・電話・メール・担当者名・自社サービス名を**ブロックリストとして**用意し、出力HTMLに混入していないか後述のセルフチェックで必ず確認すること。

### フッター帯の扱い
- **フッター帯のデザイン（色帯・装飾）は残す**が、**連絡先情報ブロックは完全削除**すること
- フッター内の `.footer-contact` クラスのdivごと削除、または `display:none` にする
- フッターには物件番号・作成日程度の最小限の情報のみ許容（会社名・連絡先は一切入れない）

### ヘッダーの扱い
- 物件名・物件番号・ハイライト情報・「📂 詳細はこちら」リンクは残す
- **会社ロゴ・会社名表記は完全削除**

### 自社サービス案内ページ（旧LINEページ等）の扱い → **ページごと完全削除**
- 自社サービス名・自社LINE案内・QRコード・自社LPへのリンクは出元が特定できてしまうため、**ページごと丸ごと削除**すること
- **概要書は4ページ構成**（ページ1〜4のみ出力）

### 置換ルール（連絡先の汎用化）
連絡先を記載する必要がどうしても生じた場合は、**汎用ラベルに置換**する：
- 「お問い合わせ：ご紹介業者様へ直接ご連絡ください」
- 「詳細は仲介業者までお問い合わせください」

### 違反時の対応
セルフチェック（後述）で1件でも会社情報が検出された場合、**修正完了するまで提出禁止**。

## 🚨 HTML完成後の必須セルフチェック（提出前ゲート）

HTMLを書き出した直後、**以下のgrepセルフチェックを必ず実行**し、結果をユーザーに報告してから提出すること。会社名・住所・電話・メール・担当者名・自社サービス名は、**自社の実際の値に置き換えて**チェックすること。

```bash
FILE="作成したHTMLの絶対パス"
echo "=== セルフチェック開始（1以上必須） ==="
grep -c "📂 詳細はこちら" "$FILE"                 # 1以上必須（共有フォルダリンク）
grep -c "drive.google.com/drive/folders" "$FILE"  # 1以上必須
grep -c "header-right" "$FILE"                     # 2以上必須（CSS定義＋HTML使用）

echo "=== 🔒 会社情報匿名化チェック（全て 0 必須／自社の値に置換して使用） ==="
grep -ic "<自社の会社名>" "$FILE"            # 0必須（会社名）
grep -c  "<自社ドメイン>" "$FILE"            # 0必須（ドメイン・メール）
grep -c  "<自社の電話番号>" "$FILE"          # 0必須（電話番号）
grep -c  "<自社の住所キーワード>" "$FILE"    # 0必須（住所）
grep -c  "<担当者名>" "$FILE"                # 0必須（担当者名）
grep -c  "<自社サービス名>" "$FILE"          # 0必須（自社サービス名）
echo "=== セルフチェック終了 ==="
```

- 「1以上必須」項目が0の場合 → 修正
- 「0必須」項目が1以上の場合 → **会社情報が残存しているため必ず削除してから再検査**

> ⚠️ **【事故記録】残存0年の建物積算価格 = 0円**
> 築古・残存耐用年数が0年の物件では、建物の積算評価が0円になる（マイナスにはならない）。
> **残存耐用年数が0以下の場合、建物積算評価は必ず0円（土地のみ）として計算すること。**

### 4ページ構成
1. 概要（ヘッダー＋**ヒーローセクション【左:KPI＋右:外観写真】**＋物件概要テーブル＋フッター帯）
2. レントロール（全戸賃料テーブル＋収入サマリー＋年間支出）
3. 収支シミュレーション＋投資ポイント＋周辺環境
4. 物件写真＋特記事項

### 最重要ルール（見落とし厳禁）

**⚠️ 費目の自動挿入禁止**
年間支出テーブルの管理費・修繕積立は、**元データ（レントロール・資料）に明記されている場合のみ記載**。元データにない場合は行ごと省略すること。標準値（管理費5%・修繕積立50万円）を勝手に挿入してはいけない。

**⚠️ ページ2・3の整合性**
2ページ目の年間支出テーブルとページ3のNOI計算式・注釈は必ず一致させること。片方を修正したら必ずもう片方も更新する。

**⚠️ 写真重複チェック必須**
外観写真を複数使う場合は、サムネイルURL（`?sz=w800`）でブラウザ確認して同一アングルの重複写真を使わないこと。重複時は周辺環境写真で差し替える。

**⚠️ 1ページ目サムネイル必須**
物件写真（JPG/PNG）または物件写真PDFが共有フォルダにある場合、**1ページ目に必ずサムネイル画像を配置すること**。写真がJPG/PNGの場合は最初の1枚、PDFの場合はPDFのFILE_IDをそのままサムネイルURLに渡す（Driveが1ページ目を自動生成）。
```html
<!-- 1ページ目サムネイル（必須） -->
<img src="https://drive.google.com/thumbnail?id={FILE_ID}&sz=w800"
     onerror="this.onerror=null; this.src='https://lh3.googleusercontent.com/d/{FILE_ID}'"
     alt="物件外観" style="width:100%; max-height:90mm; object-fit:cover; border-radius:6px; border:1px solid #c8d8f8;">
```
写真が一切ない場合のみ `<div style="background:#2d4a7a; color:rgba(255,255,255,0.3); text-align:center; padding:40px 0;">写真準備中</div>` を代替として使用。

**⚠️ 中間省略**
売主名・仲介名・元所有者名は一切記載NG。

**⚠️ 「📂 詳細はこちら」リンク（共有フォルダー）必須**
1ページ目ヘッダー右側（`.header-right` 内）に、共有フォルダーURLへのリンクボタンを必ず設置すること。これを忘れると、業者・購入検討者が詳細資料（重説・謄本・レントロール等）にアクセスできなくなる。**忘れやすい最頻出ヌケ項目なので、ヘッダー組み立て時点で必ず仕込み、完成後のgrepセルフチェックで確認すること。**

```html
<!-- ヘッダー右側 .header-right の中に必ず追加 -->
<a href="{共有フォルダURL}" target="_blank"
   style="display:inline-block; margin-top:6px; padding:4px 10px;
          background:#DAA520; color:#1A365D; border-radius:4px;
          font-size:8pt; font-weight:700; text-decoration:none;">
  📂 詳細はこちら
</a>
```

- 共有フォルダURLが空の場合のみボタン省略可（その場合はユーザーに「共有フォルダーURLが未入力です」と必ず報告）
- `target="_blank"` 必須（新しいタブで開く）

### 写真フォルダーの運用ルール（必須）

**フォルダー構成（物件フォルダー内）:**
```
物件フォルダー/
  ├── ★共有フォルダ/
  │   └── 写真フォルダ/  ← 必ず共有フォルダの中に作成する
  └── その他ファイル
```

**写真ページ（P4）の作成判断:**

| 状態 | 対応 |
|------|------|
| 共有フォルダ内に「写真フォルダ」がある | 写真フォルダ内の画像を使って写真ページを作成 |
| 共有フォルダ内に「写真フォルダ」がない | 写真ページは作成しない（スキップ） |
| 写真フォルダにPDFしかない | 写真ページは作成しない（画像ファイルが必要） |

**ファイル要件:**
- 写真フォルダには **JPEG・PNG等の画像ファイル** を入れること
- PDFファイルは写真として使用不可（Drive thumbnail URLはPDFの1ページ目しか表示できないため）
- Google Street View・Google Maps Static API・その他外部APIの使用は**禁止**

**Drive写真をWeb公開ページで表示するための条件:**
- 写真フォルダ内の全ファイルを「リンクを知っている全員（閲覧者）」に共有設定すること
- **非公開ファイルのままでは外部から読み込めない**（SameSite cookieの制限により認証が通らない）

**P4作成判断:** 写真フォルダに画像が1枚以上 → 写真ページ作成。`https://drive.google.com/thumbnail?id={FILE_ID}&sz=w800` を `<img src>` に直接使用。
画像が0枚 → P4はスキップ。

**P1ヒーローセクションの写真:** 最初の1枚を外観写真として使用。写真がない場合はグレー背景の「写真準備中」を表示。

## 投資区分の特例ルール（低価格帯・高利回り戸建て等）

> 低価格帯・高利回り・特殊計算の物件（例：戸建て投資クラブ向け）では、専用の収支シミュレーションテーブルを設けることがある。
> 想定月額賃料は**元データ（案件管理表の指定列）を参照**し、担当者が勝手に推定しないこと。

### 禁止事項
- **「内覧を勧める」「リフォームを勧める」等の営業的文言を概要書に入れない**
  - 例：「リフォーム必須」「DIYリフォーム向き」「内覧推奨」などは削除
  - 事実としての「現状引渡し」「空室」「築年数」のみ記載する
- **🔒 会社情報は一切記載しない**（上部「会社情報の完全匿名化ルール」参照）
- **瑕疵担保免責** は契約条件による場合のみ明記。安易に「免責」と書かない

### 不明項目の表記ルール
元データに記載がない場合は空欄・「記載なし」ではなく **`【確認中】`** と表記する。

### 専用収支シミュレーションテーブル（必要時）

| 項目 | 式 |
|---|---|
| **年間想定家賃収入** | 想定月額賃料 × 12 |
| **想定利回り** | 年間想定家賃収入 ÷ 販売価格 × 100（%） |
| **想定出口価格（利回り20%想定）** | 年間想定家賃収入 ÷ 0.20（＝年間家賃の5倍） |
| **想定売却益** | 想定出口価格 − 販売価格 − 諸経費 − （該当する成功報酬等の費用） |

- 諸経費（登記費用等の概算）は案件ルールに従い固定値で扱う場合がある（例：100,000円）。
- 低価格帯物件で利回りが異次元の数値（例：180%、440%等）になる場合でも計算式通り記載する（盛らない・下げない）。
- 想定出口価格は「利回り20%固定ロジック＝年間家賃÷0.20」のみ。独自の運用想定試算は行わない。
